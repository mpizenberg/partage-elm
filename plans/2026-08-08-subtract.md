## Goal

Make the repository smaller and more truthful without removing promised behavior. Delete dead mechanisms, give repeated domain rules one owner, and make the documented pnpm version range install cleanly.

## Increments

1. **Delete suppressed dead code.** Remove the unused `AttemptBatch` API and `Update.mapModel`, discard the unused scroll result payload, move the two prematurely computed values to their only branches, and delete the now-empty suppression files. Validate formatting, elm-review without suppressions, and Elm tests.
2. **Make member involvement one domain rule.** Put entry-level member extraction in `Domain.Entry` and payload-level extraction in `Domain.Event`; replace the independent copies in activity construction, filtering, and push notification targeting. Keep behavior and relevant tests unchanged while deleting the duplicate case expressions.
3. **Make installs explicit and supported.** Move dependency build permissions out of the pnpm-10-era `package.json` field into pnpm 11's `allowBuilds` configuration for the two independently locked packages. Verify frozen installs under the available pnpm 11, then run build, formatting, lint, Elm tests, relay Node tests, and relay Worker tests.
4. **Close the audit.** Re-check line/concept deltas, remove anything made obsolete, and leave systemic opportunities that need dedicated design work in `plans/simplify-backlog.md`.

## Decisions

- Keep both relay targets and all current product features; deleting Cloudflare, self-hosting, push, migration, or diagnostics would be a product-scope decision, not a cleanup justified by this audit. Alternative: maximize line removal by choosing one deployment shape or cutting secondary features. Reason: each is an explicit current promise with implementation and tests. Reversible only through a deliberate product decision.
- Do not split `Main.elm` or `Page/Group.elm` merely because they are large. Alternative: move update branches into more modules. Reason: moving code would add boundaries without yet deleting concepts; ownership redesign belongs in a dedicated task backed by a concrete simpler model.
- Treat the root app and relay as independently locked packages in this pass. Alternative: create one pnpm workspace and one lockfile. Reason: the relay's lockfile is also the self-contained Docker production install boundary; unifying it would complicate that boundary without removing dependency graph content.
- Put entry involvement on `Domain.Entry` and payload involvement on `Domain.Event`. Alternatives: retain an Activity-owned helper for Infra to import, or add a generic utility module. Reason: involvement is domain meaning used by three consumers, and these owners make both duplicate case expressions disappear without a new module.
- Use pnpm's `allowBuilds` map in each package's `pnpm-workspace.yaml`. Alternatives: pin pnpm 10 and retain the package manifest field, or allow every dependency script. Reason: the declared `pnpm >=10` range should work on 11, and an explicit per-package allowlist works on both tested majors without broadening script execution.
- Delete the commented-out `NoDebug` rules and `elm-review-debug` dependency rather than enabling them. Alternative: activate both rules and keep the package. Reason: disabled checks enforce nothing; this pass removes inert configuration, while adopting a new lint policy would be a separate decision.
